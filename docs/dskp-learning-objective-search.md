# 按 DSKP 学习目标找工具：实施规格

> 状态：已确认的产品方向，尚未实施。  
> 读者：负责课堂点子铺的开发者／Claude Code。  
> 最后更新：2026-07-21。

## 1. 要解决的问题

老师备课时通常先确定年级、科目与 DSKP 学习目标，才会寻找可用的活动或工具；他们不会预先知道某个工具或游戏的创意名称。因此，EduNeo Hub 的主要入口不应只是「按工具名称搜索」，而应让老师能按自己要教的目标直接找到合适工具。

平台要完成的路径是：

```text
今天要教什么 → 对应哪个学习目标 → 哪些工具真的适合使用 → 打开工具
```

这不是一个完整 DSKP 阅读器，也不是自动生成教案的系统。它是一个把已核对课程目标与已发布教学工具连起来的备课入口。

## 1.1 当前专案入口与阶段 A 的改动范围

现有静态原型的入口是：

- `index.html`：首页结构。
- `style.css`：首页与弹窗样式。
- `app.js`：`SUBJECTS`、`TOOLS`、搜索、筛选、详情与统计逻辑。
- `docs/dskp/tahun{N}/{subjek}.md`：人工核对过的 DSKP 摘要来源；它们不是浏览器运行时直接读取的资料格式。
- `docs/dskp/README.md`：已覆盖科目／年级与资料缺口的唯一总览。

阶段 A 可继续用原生 HTML、CSS、JavaScript，不需要引入框架、后端或 AI。建议新增一个浏览器可读的 DSKP 索引资料档（例如 `data/dskp-index.js`），由人工根据已核对摘要整理；前端只读取这个结构化索引，**不要在浏览器解析 Markdown 摘要**。

阶段 A 的最低验证方式是：为索引资料和真实工具资料写一个 Node 验证脚本，检查目标代码、年级、科目、来源网址和核对日期均存在；验证失败时不渲染该 DSKP 对照，并在开发时输出明确错误。

### 1.2 `data/dskp-index.js` 的阶段 A schema

索引档导出单一常量 `DSKP_INDEX`。一笔记录代表一个「课程版本 + 年级 + 科目」，是单元树、搜索建议、URL 校验与工具资料验证的唯一权威来源。

```js
const DSKP_INDEX = [{
  curriculum: "KSSR Semakan 2017",
  tahun: 2,
  subjek: "mt",
  sourceUrl: "官方 DSKP 文件网址",
  sourceLabel: "DSKP Matematik Tahun 2 SJK(C)",
  verifiedAt: "2026-07-21",
  units: [{
    code: "4.0",
    title_zh: "钱币",
    title_bm: "Wang",
    objectives: [
      {
        code: "4.1",
        title_zh: "纸币和硬币",
        title_bm: "Wang kertas dan duit syiling",
        terms: ["纸币", "硬币", "确认币值", "nilai wang"]
      },
      {
        code: "4.2",
        title_zh: "钱币加法",
        title_bm: "Operasi tambah wang",
        terms: ["钱币加法", "tambah wang"]
      }
    ]
  }]
}];
```

阶段 A 规则：

- 一笔索引记录的 `tahun + subjek + curriculum` 组合必须唯一。
- `unit.code` 在同一记录中唯一；`objective.code` 在同一单元中唯一，且每项目标必须有中马标题与 `terms`。
- 来源、核对日期与课程版本继承自索引记录；工具资料不得另填一个不一致版本。
- 工具的 `standards[0]` 必须精确引用同一笔索引记录和其中的单元／目标代码；前台的正式标题、来源与日期一律从 `DSKP_INDEX` 读取，避免两处资料慢慢不同步。

## 2. 产品决定

1. 首页主入口改为 **「按学习目标找工具」**；原本的自由搜索与「浏览全部工具」保留为辅助路径。
2. 工具名称可以继续有创意；老师不需要先猜到名字，仍可借由学习目标、常用教学说法、中马双语关键词找到它。
3. 只显示实际核对过的 DSKP 对照。没有核对过的工具仍可按年级、科目、名称与关键词浏览，但不能伪装成有 DSKP 对照。
4. DSKP 正式文字与老师日常会搜的词必须分开保存：前者保证可信度，后者保证搜得到。
5. 当前已建 DSKP 摘要只覆盖数学、科学、马来文、英文的 Tahun 1–6，以及华文 Tahun 1–5。尚未覆盖的科目不可承诺学习目标导航。
6. 搜索、年级与科目必须取交集；输入关键字不能覆盖已选筛选条件。
7. 公开的「可用工具」结果、喜欢数排序、使用次数统计都只包含 `status: "published"` 且有有效 `url` 的工具。`planned` 只能在未来独立的「开发中」区域出现；`archived` 不出现在默认结果中。

## 3. 老师的使用流程

### 3.1 主要路径：我知道要教的单元或目标

1. 老师进入首页，看见提问「今天要教什么？」。
2. 选择年级，例如 `Tahun 2`。
3. 系统只显示该年级有已索引 DSKP 的科目；老师选择「数学 / Matematik」。
4. 显示该科目的单元与学习目标树；老师选择「4.2 钱币加法」。
5. 结果区只显示已标注覆盖 4.2 的真实工具，并说明它为什么适合。
6. 老师查看详情，在新分页打开工具。

### 3.2 快速路径：我只知道自己要教什么

老师可直接输入：

- DSKP 代码：`4.2`
- 正式目标：`钱币加法`、`tambah wang`
- 日常用语：`找零钱`、`认硬币`
- 工具名称：`钱币乐园`、`Taman Wang`

输入时显示建议：匹配的单元、学习目标与工具；不要要求老师输入完整句子或先按 Enter。

### 3.3 不知道目标代码时

提供可点选的常用入口，例如「钱币」「分数」「时间」「阅读」「词汇」。这些入口不是另一套分类，而是已验证关键词的快捷方式，点击后仍回到对应 DSKP 目标与结果。

## 4. 首页信息架构与界面

首页第一屏建议如下：

```text
课堂点子铺
可直接带进华小课堂的互动教学工具

今天要教什么？
[ Tahun ▼ ] [ 科目 / Subjek ▼ ]
[ 搜索学习目标、代码或关键词                         ]
  例如：4.2、钱币加法、tambah wang、找零钱

常用入口：[ 钱币 ] [ 分数 ] [ 时间 ] [ 读写 ] [ 词汇 ]

当前路径：Tahun 2 › 数学 › 4.0 钱币
学习目标列表：
  4.1 纸币和硬币
  4.2 钱币加法
  4.3 钱币减法
  4.6 储蓄与投资

找到 1 个工具
```

界面规则：

- 年级未选时，科目选择器应提示「先选年级」；不要先展示一整排可能不适用的科目。
- 科目未有已核对 DSKP 索引时，要诚实说明「这个科目的学习目标索引仍在整理中」，并提供「浏览该科工具」路径。
- 结果区显示结果数量、当前筛选摘要和「清除筛选」。
- 无结果不是死路：显示已选目标，并建议浏览该单元、调整年级／科目，或提出工具建议。
- 选中状态不能只靠颜色；必须有文字、勾选或其他清晰状态。
- 所有选择器、搜索建议、结果卡和关闭按钮都必须可键盘操作，并保留明显焦点样式。
- 手机优先：每个可点目标至少 44px 高；学习目标树改为可展开的单列，不做横向滚动。

## 5. 结果卡：回答「为什么适合我」

每张结果卡除了工具名称，还必须显示：

- `对应学习目标`：例如「Tahun 2 数学 · 4.2 钱币加法」
- `可练习什么`：例如「两个／三个币值相加」
- `课堂方式`：例如「投影互动、全班／小组」
- `准备条件`：例如「打开即用」「需打印」「学生需各自设备」
- `DSKP 对照状态`：已核对时显示核对日期；未核对时不能显示具体代码。

工具可能覆盖多个目标。当老师从特定目标进入时，卡片优先突出该目标，而不是把全部标签平铺出来。

## 6. 工具资料模型

现有 `standards: { unit, items, source }` 只适合详情展示，不足以支持稳定搜索。逐步把真实工具改为以下结构；示例作品不应使用伪造 DSKP 数据。

```js
{
  slug: "tahun2-mt-wang",
  status: "published", // published | planned | archived
  tahun: 2,
  subjek: "mt",
  title_zh: "钱币乐园",
  title_bm: "Taman Wang",
  keywords: ["钱币", "wang", "找零钱", "baki"],
  teachingTags: ["投影互动", "全班活动", "小组活动", "5-15分钟", "打开即用"],
  standards: [{
    curriculum: "KSSR Semakan 2017",
    unitCode: "4.0",
    objectiveCodes: ["4.1", "4.2", "4.3", "4.6"]
  }]
}
```

资料规则：

- `objectiveCodes[]` 必须是已查证 DSKP 中的真实代码。
- `terms`、正式中马标题、`sourceUrl` 与 `verifiedAt` 全部由 `DSKP_INDEX` 提供；工具只保存引用代码，避免两份资料不同步。
- `terms` 可含中文、马来文和老师常用说法，但不得改变正式目标含义。
- `sourceUrl` 指向公开、可信的来源；前台不可显示内部档案路径如 `docs/dskp/...`。
- `verifiedAt` 让日后课纲更新时可追查与重审。
- 将来工具多时，`TOOLS` 应从 `app.js` 分离为独立资料档，并使用验证脚本检查 slug、科目、目标代码和必填字段。
- 阶段 A 的一项工具只可对应与其顶层 `tahun`、`subjek` 相同的一个 `standards` 项；跨年级、跨科目或多个课纲版本暂不支持，需另开设计决定，不能悄悄复用这套模型。
- 验证脚本必须逐一反查 `DSKP_INDEX`：工具的 `curriculum`、`tahun`、`subjek`、单元代码和每个目标代码都必须存在且完全对应。只检查字段格式或 URL 存在并不足够；找不到索引目标时必须失败。

## 7. 搜索与排序规则

### 7.1 必须同时成立的筛选

```text
年级符合 AND 科目符合 AND（没有查询词 OR 查询词匹配）
```

不能因为用户开始输入查询词，就跳过年级与科目筛选。

### 7.2 排序优先级

在同一筛选范围内，依序提高相关性：

1. 精确 DSKP 目标代码，如 `4.2`。
2. 精确目标名称或单元名称。
3. 已人工审核的中马双语同义词／老师常用语。
4. 工具标题、说明、一般关键词。
5. 工具的真实热度指标。

热度只能用于同等相关结果的排序；不能盖过与当前学习目标更准确的工具。阶段一 localStorage 的喜欢数和使用次数只是本机演示，不能当作全体老师数据。

阶段 A 的匹配规则保持可预测：查询字串先去除首尾空白、转小写，并比对代码、标题和人工维护的 `terms`；不做模糊拼写、自动翻译或 AI 推断。中文繁简转换、拼音搜索和模糊匹配可在有真实搜索日志后另行评估。资料模型已有 `title_zh`、`title_bm`、`keywords` 与工具说明字段，前三项和 `terms` 是阶段 A 的搜索来源。

### 7.3 搜索建议

当输入至少一个字符后，显示最多 5 个建议，可混合：

- 单元，例如「4.0 钱币」。
- 学习目标，例如「4.2 钱币加法」。
- 可用工具，例如「钱币乐园」。

每个建议必须标示类型，不能让老师分不清自己选的是目标还是工具。

建议的点击行为固定如下：

- 选择单元：更新 `tahun`、`subjek`、`unit`，清空 `objective`，保留查询词。
- 选择学习目标：更新 `tahun`、`subjek`、`unit`、`objective`，保留查询词，并把焦点移到结果标题。
- 选择工具：打开该工具详情弹窗；不改变现有年级／科目／目标筛选。
- 建议按「精确目标 → 单元 → 工具」排序；同类项目按相关性、正式标题排序；相同项目只显示一次。

## 8. URL 与状态

将选择同步至 URL，支持分享、重新整理与浏览器返回：

```text
?tahun=2&subjek=mt&unit=4.0&objective=4.2&q=tambah%20wang
```

URL 只储存筛选条件，不储存学校、账号、反馈内容或个人资料。

参数修正规则：

- `objective` 必须属于 `unit`、`subjek` 与 `tahun`；若不属于，忽略 `objective` 并显示可恢复的提示。
- `unit` 必须属于 `subjek` 与 `tahun`；若不属于，忽略 `unit` 与 `objective`。
- `tahun` 或 `subjek` 无效时，回退至「全部」状态。
- `q` 永远只是额外查询条件，不会覆盖有效的年级、科目、单元或目标。

## 9. 分阶段实施

### 阶段 A：可信的 DSKP 导航（下一项功能）

- 先支持已有可靠摘要的科目与年级。
- 建立 DSKP 索引资料，不需先做完整后台或账号系统。
- 为每个**真实已发布工具**人工标注实际覆盖的目标；先从钱币乐园开始。
- 首页加入年级 → 科目 → 单元／目标导航、结果数量、清除筛选与无结果引导。
- 修正现有搜索与筛选未取交集的问题。
- 支持 URL 状态与中马双语／同义词搜索。

### 阶段 B：资料覆盖与质量控制

- 按真实工具开发优先顺序补足 DSKP 索引，不为了视觉完整而编造其他科目资料。
- 建立工具登记模板与资料验证脚本。
- 为每个目标记录 DSKP 版本、来源、核对日期和维护者。
- 在详情页显示「对应学习目标」与课堂方式标签。

### 阶段 C：AI 辅助理解自然语言（未来计划）

目标：协助老师把自然语言需求转成候选的年级、科目、单元或学习目标。例如：

> 「我要让二年级学生练习给 RM10 找零钱。」

AI 可建议「Tahun 2 数学 → 4.0 钱币 → 4.3 钱币减法」，并列出相符工具。

**AI 的边界：**

1. AI 只能从已建立、已核对的 DSKP 索引中检索与排序；不能自行发明目标代码、课程标准或工具关联。
2. 每个建议都必须显示 DSKP 代码、正式名称、来源与「为什么推荐」。
3. 未覆盖科目、资料不足或信心不足时，AI 必须明确说「尚未有足够已核对资料」，并退回普通关键词搜索或工具建议入口。
4. AI 结果是建议，不是课程官方解释；页面须允许老师一键改选年级、科目和目标。
5. 初期不要上传学生个人资料、学生作品、课堂录音或学校资料给 AI。自然语言查询应最小化记录，且须有清楚的隐私说明。
6. 评估 AI 时，以老师能否更快找到正确目标为准，而不是回答写得是否流畅。

建议技术路径：先完成结构化 DSKP 索引与普通搜索；未来 AI 只调用该索引做受限检索（retrieval），而不是直接根据模型记忆回答课程问题。

## 10. 验收条件

阶段 A 完成前，至少满足：

- 输入「4.2」「钱币加法」「tambah wang」「找零钱」都能找到钱币乐园（若对应关系已核对）。
- 选择 `Tahun 2 + 数学` 后搜索「成语」，结果必须为 0，不能出现三年级华文工具。
- 选择不在已索引范围内的科目时，清楚显示资料状态与替代路径。
- 结果卡能说明匹配的学习目标、课堂方式与 DSKP 核对状态。
- 键盘可完成选择、搜索、打开建议与清除筛选；手机没有横向滚动，触控目标至少 44px。
- 复制带筛选的网址，在新浏览器打开后能还原相同筛选状态。
- 任何前台 DSKP 对照都有来源与核对日期；示例／未验证工具不会显示伪造对照。
- 默认结果与统计只计算 `status: "published"` 且有有效 URL 的工具。
- 资料验证脚本会拒绝缺少 `verifiedAt`、`sourceUrl`、目标代码或与工具年级／科目不一致的 DSKP 对照。

## 11. 上线前的小型教师测试

找 5 位不同年级或科目的华小老师，每人完成 3 个真实任务，例如：

1. 找到「二年级数学：钱币加法」可用工具。
2. 找到「三年级科学：太阳系」相关资源；若尚无工具，理解下一步可做什么。
3. 不知道代码，只输入「找零钱」，找到对应目标与工具。

记录：是否首次就走对路径、完成时间、是否理解 DSKP 对照、在哪里卡住。根据结果改用词与同义词，不先急着扩大功能。

## 12. 非本阶段目标

- 不做完整 DSKP 全文阅读器。
- 不由 AI 自动判定或生成未经核对的课程对照。
- 不以 DSKP 搜索取代现有的自由搜索、年级／科目浏览。
- 不因要做 AI 而延后阶段 A 的结构化导航。
