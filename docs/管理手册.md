## 1. 一页看懂

### 1.1 点子铺是什么

一个给全马华小老师共享教学工具的网站。网址：https://kongsi-idea.vercel.app 。口号：**老师有点子，课堂有办法。**

做法：老师提想法（许愿），你把它打磨成真正好用的工具之后才上架。宁可少，也要每个都对课堂有帮助。（agents.md「专案简介」）

目前（2026-10-17）登记了 **54 个工具**，其中 6 份复习卷合成 3 张卡，所以首页看到约 51 张卡。年级分布：一年级 27、二年级 17、三年级 5、四年级 3、五年级 1、六年级 1。

### 1.2 有哪几部分

| 部分 | 网址 | 做什么（一两句） | 谁会用 |
|---|---|---|---|
| 首页 | `kongsi-idea.vercel.app` | 搜索、按年级／科目／主题找工具；卡片点开看详情；底部有统计条、「为什么会有这个地方」和 Telegram 联络。 | 老师、学生 |

### 1.3 三个仓库／项目的关系（一句话版）

- **`kongsi-idea/`**（Hub，中枢）：首页、详情、许愿池、kelasku、后台、工具的「登记资料」和缩略图。**不放工具本身的程式。**
- **`teaching-tools/`**：每个工具一个文件夹，各自独立的 Git 仓库和 Vercel 网站（如 `tahun5-mt-data.vercel.app`）。
- Hub 只是用网址链到各工具。改一个工具，不会牵动 Hub 或别的工具。（决定 3）

## 2. 常做的事怎么做

> 约定：下面「交给 agent 时怎么说」是你对 agent 说的话的范例。agent 会去读 `agents.md` 和 `teaching-tools/agents.md` 里的完整规则，你不用背。

### 2.1 上架新工具（含许愿池来的）

**你要做什么：** 三个关口你要在场——① 确认方案（教学目标 + 学生困难 + 玩法）；② 说「可以发布」；③ 看一眼 Hub 上的结果。其余 agent 做。
**规则出处：** `../teaching-tools/agents.md`「从许愿池做工具的标准流程」「上架到课堂点子铺的回连清单」；Hub 决定 11、13、14、30、35、37。

步骤：

1. **读单、判断够不够**。agent 读许愿单，回你三类：够的／缺的／可以先做的。你拍板做不做。（没有你确认方案，不可直接生成或发布。）
2. **做第一版**。缺的资料不停工，先按已知做出可用版，同时发信问许愿老师。做完 agent 先自己验收。
3. **上线工具本身**：建 GitHub 仓库、部署 Vercel（团队必须是 `kongsi-idea`）、接上自动部署。你说「可以发布」后，agent 自己做到底，不会叫你跑命令。
4. **登记进 Hub**（agent 做，你要知道有这些项目）：
   - `data/tools.js` 加工具条目：中英文名、说明、关键词、署名、版本、更新记录、缩略图、课标对照 `standards`、上课方式 `modes`。
   - `data/dskp-index.js` 补课标记录（只收工具实际覆盖的单元）。
   - `docs/published-tools-coverage.md` 加一行；`teaching-tools` 里跑 `npm run status:sync`。
   - 缩略图 4 张，放 `assets/thumbs/{slug}/`，跑 `scripts/build-thumbs.py` 生成网页用小图。
   - 要老师后台的：加 `data/teacher/{slug}.js` 设定，再把 slug 写进 `data/teacher/index.js`。
5. **部署 Hub 并验证线上**（见 2.8）。没验线上，agent 只能说「已提交，未验证上线」。
6. **许愿池来的，要收尾**：
   - 回许愿池把那张单改成 `shipped`，填关联工具和备注（agent 用程式直连数据库改，你也可以在 `admin.html` 自己改）。
   - 写一封给许愿老师的 **Gmail 草稿**（系统不让自动寄出），你确认后自己按发送。信里要欢迎老师回信提意见、问不超过 4 个具体问题、问署名。交付慢了要诚恳道歉一句。
   - 老师回信后：改题库、Hub 升版、写更新记录，再回信告诉他改了什么。

**署名怎么写：** 许愿单没写署名 → 「一位×年级老师」，**不写卢老师、不写学校**。有写就照写。「卢老师」只给你自己主动做的工具。工具页面里面一律不写人名，署名只放 Hub。（决定 14、30）

**交给 agent 时怎么说：**
> 「读一下许愿池新的那一单，告诉我够不够做。」
> 「方案可以，做吧。」（关口①）
> 「可以发布。」（关口②，之后 agent 会部署并上架到 Hub）

### 2.2 工具改版后，Hub 要同步什么

**什么时候：** 工具本身有学生看得到的改动（新题、新玩法、修错）。
**一句话：** 工具部署完不算完，**Hub 同步是完成的一部分**。（`teaching-tools/agents.md`；2026-09-17 浮沉实验室 v2.0 上线了 Hub 却还是 v1，被你点名过。）

agent 要逐项做完：

1. `data/tools.js`：`version` 升版，`changelog` 在最前面加一条（版本、上线日期、改了什么）。说明、关键词、课堂方式如果因改版失效，一并改。
2. 用正式网址重新截图，换进 `assets/thumbs/{slug}/`（新档名带版本），旧图搬到「待删除」，再跑 `build-thumbs.py`。
3. `docs/published-tools-coverage.md` 该行「优化备注」写上版本和日期。
4. `teaching-tools/tools-status.json` 更新版本和日期，跑 `npm run status:sync`。
5. Hub 提交推送，再走 2.8 的部署三步，最后确认线上 `data/tools.js` 真的有新版本号。

**不用升版的情况：** Hub 自己的整理改版（首页、详情页、后台、搬登记位置），学生那边没变，**不升工具版本、不写 changelog**，只记在 Hub 的提交信息、`agents.md` 和 `handoff.md`。（决定 38）

**交给 agent 时怎么说：**
> 「XX 工具改好了，上线并把 Hub 同步到位，做完告诉我线上看到的版本号。」

### 2.4 处理许愿单

1. 打开 `kongsi-idea.vercel.app/admin.html`，用你的 Google 登录。
2. 页签：全部／新提交／已看过／研究中／已排期／制作中／已上架／不做，另有「注册名单」。
3. 每张单可改**状态**、**备注**、**关联工具**。看到单子就先改成「已看过」，做完改成「已上架」并填工具名。做不了就改「不做」并写原因。
4. 判断够不够做的标准：开发者读完能不能知道怎么设计。特别看「错例」栏有没有写**一道具体的题 + 学生真的答错的答案**，而不是一句概括。（决定 31；`idea-wish-pool-spec.md` 3.3）
5. 信息不够，就写信问老师（Gmail 草稿，你确认后寄）。
6. 许愿默认不公开老师和学校。不收集学生个人资料。（决定 12、30）

### 2.7 把自己的设备设成不计数（`?nocount=1`）

目的：你自己测试、展示时，不要灌水统计。

1. 在你要排除的**每一台设备、每一个浏览器**上，用网址打开一次：
   `https://kongsi-idea.vercel.app/?nocount=1`
   之后这台浏览器打开 Hub 就不计到访和工具使用。
2. **工具网址要分开设。** 浏览器的记忆是按网站分开的，Hub 设了不等于工具也设了。你若会直接打开某个工具的网址，在那个网址后面也加 `?nocount=1` 打开一次（例如 `https://tahun5-mt-data.vercel.app/?nocount=1`）。从 Hub 点「开始使用」进去的，工具本来就会跳过，不用再设。（`data/track-use.js` 注释：「只影响这台浏览器的这个工具」）
3. 取消：`?nocount=0`。
4. 无痕模式、清缓存、换浏览器后记忆会没，要重设。
5. 2026-10-17 之前的数字里，已经包含你和测试的使用，补不回来。

### 2.8 部署与回滚 Hub

**先记住最重要的差别：**

| | Hub（kongsi-idea） | 各个工具（tahun…） |
|---|---|---|
| `git push` 之后 | **不会上线** | **自动部署**（GitHub Actions） |
| 要做什么 | 手动部署，再验证 | 平时只要 push；失灵时用 `npm run deploy -- <slug>` |

Hub 的固定收尾（决定「部署」一节；handoff 注意事项）：

1. 在 `kongsi-idea/` 里跑 `vercel --prod --yes`。
2. 到 Vercel 的 Domains 列表确认 `kongsi-idea.vercel.app` 还在这个项目上。（它曾经整个消失过，决定 16。）
3. `curl` 线上档案，确认**这次改动独有的内容**真的在（例如 `curl -s https://kongsi-idea.vercel.app/data/tools.js | grep 新版本号`）。
4. 没做第 3 步，只能说「已提交，未验证上线」。

两个已知的坑：
- 文档原本写的第二步 `vercel alias set …` 现在会报「找不到」（命令行默认团队不对）。2026-10-17 的实际情况是 `vercel --prod` 本身已把正式网域指到新版，线上已确认。所以**以第 3 步的线上验证为准**。（handoff）
- `vercel --prod` 的自动别名有时指错到 `eduneo-hub.vercel.app`，要核对 `kongsi-idea.vercel.app`。（handoff）
- 线上完全没反应时，**先查 Domains 列表**，不要只重跑部署。加回域名的方式见决定 16。

**回滚：** `agents.md` 和 `handoff.md` 里**没有写明 Hub 的回滚步骤**（未确认）。一般做法是：用 `git revert` 退回有问题的提交，再重走上面三步；或在 Vercel 后台把上一个部署设回正式。这是通用做法，没有在本项目实测过。agent 做完部署时，会按规则回报「提交号、线上证据、回滚指令」。

**权限：** Hub 本体 `kongsi-idea` 在你授权的手动部署名单里。**下面几个动作会被系统挡，不是出错：** 授权名单外的生产部署、数据库结构变更（深夜 23:00–09:00 更挡）、`rm -r/-f`、寄出 Email。

**交给 agent 时怎么说：**
> 「把 Hub 部署上线，做完告诉我线上验证结果。」
> 「线上好像还是旧的，先查 Domains。」

## 3. 要注意的事

挑出会影响你判断的 16 条。技术细节放第 5 节。

| # | 是什么（白话） | 为什么 | 违反会怎样 |
|---|---|---|---|
