# 点子许愿池：结构化需求收集规格

> 状态：已确认产品方向，尚未实施。  
> 读者：负责课堂点子铺的开发者／Claude Code。  
> 最后更新：2026-07-21。

## 1. 目的

「点子许愿池」不是让老师随手留一句“想要一个游戏”的意见箱，而是把老师实际遇到的课堂问题整理成可理解、可排优先级、可设计的教学工具需求。

目标是收集以下四件事：

```text
在哪一堂课发生 → 希望学生做到什么 → 目前卡在哪里 → 什么方式会真正有帮助
```

开发者负责把零散需求归类、合并与验证，不要求老师先想出完整功能、工具名称或技术解法。

## 2. 产品定位与边界

- 名称：**点子许愿池**。
- 对外说明：**你教室里卡住的地方，写下来；我们一起想办法。**
- 它收集的是教学工具构想与课堂问题，不是一般客服、帐号问题、学生个案辅导或学校行政投诉入口。
- 提交后默认不公开；先由平台审核与合并相似需求，避免老师资料或课堂细节直接暴露。
- 不承诺每一则需求都会开发；承诺会依课堂影响、重复出现程度、可行性与现有 DSKP 覆盖情况评估。
- 不把“老师声望星星”作为填写诱因。未来若有贡献机制，应奖励有帮助的补充与验证，而不是鼓励大量短讯息。

## 3. 填写体验

表单应是约 2 分钟的引导式短表单，不是一页塞满的长问卷。分成 3 步，并在顶部显示「第 1／3 步」与可返回按钮；每一步只问当前必要问题。

```text
第 1 步：这堂课
第 2 步：学生卡在哪里
第 3 步：你希望怎样帮上忙
```

必要资料用 `*` 标示；其他问题明确写「选填」。老师不知道 DSKP 代码时，绝不能因此无法提交。

### 3.1 选项 ID 与验证规则

所有前端显示文字可调整，但储存值固定如下，避免前后端和统计各自使用不同名称：

```js
const LESSON_MOMENTS = ["introduction", "explanation", "practice", "review", "assessment", "remedial"];
const DIFFICULTY_TAGS = ["concept", "steps", "engagement", "mixed-ability", "visibility", "prep-time", "other"];
const CONSTRAINTS = ["teacher-projector", "no-student-devices", "unstable-network", "no-printing", "short-lesson", "large-class", "other"];
const DESIRED_HELP = ["classroom-interactive", "practice-game", "presentation-aid", "group-activity", "printable", "utility", "unsure"];
const USAGE_MODES = ["whole-class", "pair-group", "independent", "teacher-prep", "no-device"];
```

- `learningGoal`：必填；只作「1–2 句」提示，不限制句数；去除首尾空白后至少 8 个 Unicode 字符。
- `problemDescription`：必填；去除首尾空白后以 Unicode 字符数计算，至少 20 个字符。
- `difficultyTags`、`constraints`、`usageModes` 可多选；选择 `other` 时显示一个选填的补充文字栏。
- `desiredHelp` 只能选一项；选择 `unsure` 合法，不能阻止提交。

### 3.2 草稿规则

阶段 A 的草稿只存于当前浏览器的 `localStorage`，键名为 `classroom-idea-shop-wish-draft-v1`；不上传服务器、不与账号同步。

- 自动暂存年级、科目、DSKP 选择、课堂问题与工具偏好；**不暂存学校资料和隐私确认**。
- 首次关闭已有内容的表单时，询问「暂存到这台设备」或「放弃内容」；不得静默储存。
- 成功提交、用户明确放弃、或 30 天后，删除草稿。
- 再次打开时，若草稿仍有效，询问是否恢复；不自动填入并提交。

### 第 1 步：这堂课

| 字段 | 必填 | 设计与用途 |
|---|---:|---|
| 年级 | 是 | Tahun 1–6；用于把需求放进正确课程语境。 |
| 科目 | 是 | 只显示该年级可选科目；与 DSKP 搜索共用科目资料。 |
| 单元／学习目标 | 否 | 可按 DSKP 树选择，也可搜索代码或关键词；不知道时可跳过。若从 DSKP 搜索页面进来，应自动带入。 |
| 这堂课在教什么？ | 是 | 1–2 句，聚焦学生要学会什么，而不是先规定工具。提示：「学生在这一课结束时，应该能做到什么？」 |
| 上课场景 | 否 | 单选：新课引入／讲解中／练习巩固／复习／评估前／课后补救。 |

### 第 2 步：学生卡在哪里

| 字段 | 必填 | 设计与用途 |
|---|---:|---|
| 现在最难的是什么？ | 是 | 文字框，最少 20 字。提示：「学生做了什么、说了什么，或哪里一直做错？」 |
| 常见困难 | 否 | 可多选：听不懂概念／容易混淆步骤／缺少练习动机／程度差异大／全班互动不够／难以快速看见谁会谁不会／准备材料太花时间／其他。 |
| 你已经试过什么？ | 否 | 让开发者避免重复做老师已有的办法，也可了解现有工具为何不足。 |
| 有什么限制？ | 否 | 可多选：只有教师投影／学生没有个人设备／网络不稳定／不能打印／课时很短／班级人数多／其他。 |

### 第 3 步：你希望怎样帮上忙

| 字段 | 必填 | 设计与用途 |
|---|---:|---|
| 最希望得到哪种帮助？ | 是 | 单选：课堂互动工具／练习或小游戏／投影讲解辅助／分组活动／可打印材料／随机抽选或计时工具／还不确定。 |
| 希望怎样使用？ | 否 | 可多选：全班投影／两人或小组／学生自己练习／老师课前准备／没有设备也能用。 |
| 必须有／不要有 | 否 | 文字框。例如「要能在 10 分钟内完成；不要要求学生注册」。 |
| 课堂情境补充 | 否 | 文字框；可写一个真实但不含学生姓名的例子。 |
| 学校 | 否 | 州属→县→学校选择或手动输入。只用于汇总覆盖范围，必须可跳过，并说明不会公开显示。 |

## 4. 关键文案与示例

### 开场文案

> **你教室里卡住的地方，写下来。**  
> 不用先想好要做什么工具；告诉我们学生要学什么、现在难在哪里，我们一起想办法。

### 不够具体的写法

> 想要一个分数游戏。

### 好的填写示例

> 五年级数学教分数加法时，学生常把分母也直接相加。我已经用分数图讲过，但程度较弱的学生还是跟不上。希望有一个可以投影、让全班轮流操作的短活动，10 分钟内能看出谁理解了同分母分数加法。

示例的作用是教老师描述问题，不是要求他们写得像教案。不要把它做成默认填入文字。

### 提交成功文案

> **点子已经放进铺里。**  
> 我们会先和相似需求放在一起看看，再评估最能帮到课堂的做法。开发进度不会自动承诺，但你的描述会帮助我们把工具做得更对症。

## 5. 前端行为与无障碍要求

- 每个输入必须有可见的 `<label>`，不能只靠 placeholder。
- 文字框在离开输入框时才验证；错误显示在对应字段下方，并用 `aria-live`／`role="alert"` 宣告。
- 不要要求用户在每一步完成时填写所有选填项；只有必填项不完整时才阻止下一步。
- 每个选择卡、单选按钮、多选按钮与上一步／下一步按钮的触控范围至少 44px，键盘 Tab 顺序与视觉顺序一致。
- 选择 DSKP 目标时使用原生按钮或可访问的树状／展开组件；目标代码、标题和已选状态不能只靠颜色传达。
- 进度条必须以文字表达「第 2／3 步：学生卡在哪里」，而不是只显示三颗圆点。
- 关闭弹窗、返回和离开未提交需求时要有明确路径；有内容未提交时提示是否保留草稿或放弃。
- 提交时按钮显示「正在送出」，防止重复送出；成功／失败必须有明确文字和重试方式。
- 不收集学生姓名、照片、成绩单、课堂录音或其他可识别学生资料；提示老师移除这些内容。

## 6. 前端资料结构

阶段一可先在前端维护表单状态；真正提交必须等后端、审核与隐私说明准备完成后再开启。

```js
{
  tahun: 5,
  subjek: "mt",
  dskp: {
    curriculum: "KSSR Semakan 2017",
    unitCode: "3.0",          // 可为空
    objectiveCode: "3.2"      // 可为空
  },
  learningGoal: "学生能理解同分母分数加法",
  lessonMoment: "practice",
  problemDescription: "学生把分母也直接相加，分数图讲解后仍常做错。",
  difficultyTags: ["concept", "mixed-ability"],
  triedAlready: "用分数图和练习纸讲解。",
  constraints: ["teacher-projector", "short-lesson"],
  desiredHelp: "classroom-interactive",
  usageModes: ["whole-class"],
  mustHaveOrAvoid: "10 分钟内完成；不要学生注册。",
  classroomContext: "40 人班级。",
  school: { state: "", district: "", name: "" },
  consent: true
}
```

`consent` 必须是提交前的必选确认框：

> 我知道需求会由平台团队阅读与汇总，且我没有填写学生个人资料。

学校资料不属于 `consent` 的必要条件；未填学校同样可以提交。

### 6.1 现有资料来源与学校兜底

- 年级、科目资料阶段 A 复用 `app.js` 的 `TAHUN` 与 `SUBJECTS`；年级变化后，依该资料表的适用规则显示科目。
- DSKP 目标选择与预填规则复用 `docs/dskp-learning-objective-search.md` 定义的 `data/dskp-index.js`／`DSKP_INDEX`。在该索引尚未建立前，隐藏目标树和目标搜索，但保留年级、科目与自然语言目标填写。
- 学校选择复用 `data/sjkc-schools.js` 的 `SJKC_SCHOOLS`：州属 → 县 → 学校。选到名录学校时写入 `{ source: "directory", state, district, name }`；选择「都不是，我自己打校名」时显示输入框，写入 `{ source: "manual", state, district, name }`。
- 学校整组字段可为空。手动输入学校至少 2 个 Unicode 字符；没有选择州属／县属也可手动输入，不能阻止提交。

## 7. 后端与审核流程（未来）

提交后建立内部需求记录，而不是直接公开贴在前台。建议状态：

```text
new → triaged → needs-clarification
               └→ researching → planned → building → shipped
                              └→ merged / not-planned
```

`needs-clarification` 是正式状态，不是备注；表示资料不足以判断，应在可能时向原提交老师追问，或等待更多相似需求佐证。

审核时，开发者应：

1. 删除个人资料或不适合公开的内容。
2. 将相似需求合并为一个问题主题，并保留来源数量而非公开原文。
3. 核对年级、科目与 DSKP 目标；资料不足时标为「待澄清」，而不是自行猜测。
4. 评估影响范围、重复需求量、课堂可行性、开发成本和现有工具缺口。
5. 将开发完成的工具回连到已合并需求；若不做，也标出简短原因。

未来如果让老师查看自己的提交，应只显示自己的需求与处理状态；不要默认公开老师、学校或原始文字。

## 8. 与 DSKP 搜索的连接

- 老师从「按学习目标找工具」页面没有找到结果时，显示 CTA：**「找不到合适工具？告诉我们这堂课卡在哪里」**。
- 点击 CTA 自动带入年级、科目、单元和学习目标，减少重复填写。
- 若没有 DSKP 索引，老师仍可提交；表单只收集年级、科目与自然语言目标。
- 未来 AI 只能协助把自然语言需求映射到已核对的 DSKP 索引，并把建议交给老师确认；AI 不可替老师或审核者自动决定目标代码。

## 9. 阶段安排

### 阶段 A：现在的原型调整

- 将按钮与弹窗名称改为「点子许愿池」。
- 以三步表单取代单一 textarea；先完成前端流程、必填验证与本机草稿保留。
- 没有后端时，主按钮显示「点子收集即将开放」且不可提交；不得显示成功／失败状态。
- 若改用真实、受控的临时收集管道，才可将主按钮改为提交，并实现该管道真实的「正在送出／已收到／送出失败，可重试」状态。
- 移除「星星会记在你身上」等未上线承诺。

### 阶段 B：可受理的需求收集

- 先补隐私说明、审核方式、反馈联络机制与资料保存规则，再接后端。
- 实作真实提交、内部需求状态和相似需求合并。
- 从 DSKP 搜索结果预填表单。

### 阶段 C：社群与贡献机制

- 只有在审核和隐私流程成熟后，才考虑让老师投票、补充案例或公开讨论。
- 贡献机制奖励被采纳、被验证或提供有效补充的需求，不奖励无内容的提交数量。

## 10. 验收条件

- 老师能在约 2 分钟内完成一则完整需求，不知道 DSKP 代码仍可提交。
- 每则有效需求都含年级、科目、学生学习目标、问题描述与希望得到的帮助类型。
- 开发者只看一则需求，就能判断教学场景、痛点、限制和预期使用方式；若资料不足，能明确知道要追问什么。
- 老师不会被要求提供学校或学生个人资料才能提交。
- 任何未接后端的原型都不会显示“已提交”或假装保存成功。
- 从 DSKP 无结果页进入时，年级、科目和目标会自动带入表单。
- 所有必填字段、错误、提交状态和离开未提交内容的处理都符合第 5 节无障碍要求。
